# ENG-124 + ENG-125 + ENG-130: settle survives main moving, the merge train, full settle logs

Read ENG-124, ENG-125 (including its velocity acceptance note) and ENG-130 (record show). One lane, because all three
change settle/ and promote/.

1. ENG-124: when the integration branch moves during an incomplete settle, --retry recaptures main and rebases a
   clean lane as intake does, keeping completed review evidence when the replayed tree matches. Today --retry pins the
   stale main and a fresh settle is refused, so the only exit is a new worker run.
2. ENG-125: promotion batches in the promote queue. Whatever is promotable when the queue is free goes now (no waiting
   to accumulate, no timers); stack the batch on main in scratch, run the promotion tier once, fast-forward; on red,
   split and retry halves until the breaking lane is isolated, land the rest. Settle becomes code review only, like a review on a
   pull request: it reads the diff and checks the report, and runs no test suite. The batch is the CI: the full
   promotion tier runs once per batch, right before main moves, and a tree that already has a green receipt is not
   re-run. Record report-to-main time per lane.
3. ENG-130: settle keeps the whole validation log (or head plus tail with the TAP totals) where the reviewer reads it;
   today a 8 KiB cap makes passing reviews escalate as unverified.

Failure-path acceptance: main moves mid-settle and --retry finishes without a worker run; a batch of three with one
breaking lane lands the other two and isolates the third in at most two extra runs; a lone ready lane promotes with
one promotion-tier run and no added wait; an interrupted batch leaves main untouched and is resumable; promotion
never pushes and never creates merge commits.
