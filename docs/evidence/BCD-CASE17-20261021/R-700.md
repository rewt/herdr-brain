# Case 17 queue timing correction

R-700 follows the queue-overrun review of `e24040454aed25d503b17df8175a6f652534c78f`.
The earlier 10.036-second number is an envelope assembled from different runs'
phase maxima, not a measured queue completion. A new native probe measured an
actual **12.217-second** completion. Its cost was guarded cleanup, especially
scratch scanning. The exact cause of the original release's timeout remains
unproved: this new observation exceeded the ten-second base, but stayed inside
its original load-scaled effective deadline.

## Bounded measurements

Exactly three attempts were made, with no artificial delays or extra files to
increase queue cost: two native case-body probes and one alongside the focused
heavy suite below. No live release harness or `--skip-live` pass ran. Only the
normal 150 ms queue observation cadence was used. These probes run the actual
Git, record, gate, fast-forward and guarded close path; Herdr/model transport
remains scripted. Temporary instrumentation wrapped phase boundaries, native
retirement commands and train receipt writes; no probe or instrumentation is
committed.

No attempt was retried. Whole-case failures are retained as failures; the first

## Actual completion above the ten-second base

Native 1 started observing the queue at `2026-10-21T14:07:58.843Z`, using Node
20.19.4. Its wait-start 1/5/15-minute load was
`6.38916015625 / 5.130859375 / 4.79931640625` on 18 CPUs. The shared response
rule divides one-minute load by at most four CPUs, giving factor
`1.5972900390625`. Thus the original ten-second base would have allowed
**15,973 ms**; the current sixteen-second base allowed **25,557 ms**. Neither
would have expired on this probe. The queue-operation peak was 6.8193359375,
so the separate all-CPU heavy-load classifier was false throughout.

| Phase | Native 1, ms | Scope |
| --- | ---: | --- |
| Worker spawn and acknowledgement | 99.62 | Completed 51 ms before the queue wait began. |
| Train total | 1,073.07 | Includes worker preparation, gate and fast-forward; partly overlaps the start of observation. |
| Gate | 285.53 | Within train, from its validation receipt. |

| Observed queue completion | **12,217** | From wait start to successful observation, before archiving receipts. |

Subphase rows are included in their parent; they must not be summed again.
Guarded cleanup accounts for 83.7% of the observation, and scratch preparation
for 62.2%. Host inventory at measurement setup had 90,105 entries in the user
temp root and 57,217 in `/private/tmp`. The three cwd-only `lsof` calls totaled
627.77 ms. No all-open-file `lsof` inventory ran, and the longest
`lane-promote.lock` acquisition was 1.77 ms. The measured cause of this
above-ten-second completion is therefore the guarded lane-close path, dominated
by its scratch scan, rather than gate/FF or promotion-lock contention. This
identifies the cost in this run, not the exact syscall behind the original live
timeout.

## Budget decision

Keep option (a), the **16-second base**, and the existing one-time load scaling.
The original derivation was the cross-run phase envelope of 10.036 seconds,
including polling, multiplied by 1.5 and rounded up to a whole second. It was
never an observed overrun.

Including the new trace, the corresponding cross-run maximum envelope is
1.073 seconds train + 0.376 closeout + 10.230 cleanup + 0.496 delivery + 0.150
polling, conservatively rounded up to **12.326 seconds** from the unrounded
timings in `budget.json`. A 16-second base leaves **3.674 seconds (29.8%)**
above that updated envelope,
before load scaling; the old 50% margin claim does not describe this updated
envelope. This remains a bounded observation allowance with measured headroom;
the new probe's current effective deadline also exceeds completion by 13.340
seconds. It is not a promise to cover every operational lock's maximum wait.
No additional queue optimization outside the measured bottleneck is justified
by these timings. ENG-511 owns `lib/scratch-sweep.mjs` and
`lib/lane-removal.mjs`; revisit the base after its cleanup changes land.
