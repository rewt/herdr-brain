# Verify once

The operator's 2026-10-25 overnight direction is effective immediately in Brain
and BCH, using their existing separate tooling. It supersedes routine double or
triple verification and supervisor-only landing instructions. This reference adds
no program, schema, approval stage, monitor or release. The installed sealed c160
release stays active and immutable; live instructions do not claim runtime adoption.

For each routine fact/snapshot, designate ONE verifier and put their name,
scope/source, observation time, result and evidence locator in the existing
report/receipt/note. The producer is normally that verifier. A compact receipt is
enough: `verified_by: R-852 owning engineer; fact: focused docs consistency;
source: candidate commit; at: actual receipt time; result: actual exit/TAP;
evidence: gate/log locator`. This is an example, not execution evidence.
Unknown or unrun remains UNKNOWN or unrun, never PASS.

| Fact or decision | Designated party and existing evidence | Consumer action |
|---|---|---|
| Authored source and focused check | Owning engineer; exact commit/paths and command/result/log | Supervisor and Brain Chat accept once; no rehash, binding handshake or rerun. |
| Native launch/claim | Existing dispatch/ownership controller; actual native identity and claim receipt | Consume its receipt; session/display metadata grants no authority. |
| Report bytes and ingestion | Existing record intake; immutable report/ingest receipt | Consume the scoped validation; it does not prove every report claim. |
| Landing | Owning engineer through existing lane promote; actual guard/FF and waiver receipt | Accept the actual landed result once; waived admission is executed:false, exit_code:null. |
| Independent post-code judgment | ONE independent reviewer; immutable diff/evidence and verdict | Read findings; zero tests/build/install/prepare/check/probe suites. No second full review chain. |
| Later lifecycle mutation | Existing executor; fresh native identity/claim/source/Git/CAS/HOLD/STOP evidence at that write | Consume once; a previous snapshot cannot authorize a changed target. |
| BCH state/application | supervisor-opus or original BCH owner; their own report/evidence | Brain consumes once and never edits another identity's files. |

Fresh machine guards at each NEW mutation boundary remain mandatory: actual native
identity, ownership/claims, source/head, clean Git, clean rebase, CAS and FF, live
jobs/references, recoverable archives, HOLD and STOP. They protect that mutation;
they are not a request for another conversational audit of the same fact. A concrete
contradiction, changed relevant input or missing evidence goes back to the designated
owner for the affected fact only. Preserve unaffected evidence and keep work moving.
Brain Chat spot-checks reserved/outward permissions, publishing, funds and
operator-command boundaries or concrete contested exceptions. Do not classify all
routine hashes/bindings as reserved to recreate duplicate verification.

The finishing engineer self-lands OWN source through existing lane promote with
the explicit current operator waiver, without waiting for root acknowledgment,
supervisor acknowledgment, tests or review readiness. Start exactly ONE async,
nonblocking independent post-code diff/evidence review through the existing route:
cap1, approximately 30-minute advisory target, timeout0, zero reviewer suites.
Own at most ONE formal fix round, then fix forward. Majors must actually be fixed
and their specific correction/evidence checked before a future final release.
Preserve historical verdicts/caps and actual failures. Ordinary notices return to
the owning worker via existing supported mechanisms; actual unsafe/native/identity/
ownership/reserved/failed exceptions go to that worker's PROJECT SUPERVISOR at
its supported project-specific address. Existing bootstrap watchers retain their
recorded recipient; do not duplicate or restart them.

Current-source dispatch briefs resolve the explicit parent
`MONITOR_SUPERVISOR_AGENT`, then effective project launch env, then the target
project's effective `promote.to`. Missing addresses remain UNKNOWN; dispatch does
not invent a recipient or add an address readiness gate. Each identity's owner
sets its actual project address. Older installed/saved prompts may retain their
legacy fallback; source edits change no installed binary/config/pin, saved job,
watcher recipient or claim.

Use the prescribed native protected execution from the outset for Git/control/
record/dispatch/settle/promote mutations. A native refusal stops the affected action;
never retry, relay or alternate-execute it. Preserve exact argv/cwd/context/error and
established cause or UNKNOWN in the existing morning addendum for one 08:00 decision;
no overnight operator wait/widget. Continue independently authorized non-Git work.

rerunning their audits. Reuse existing native observations, record events and action
receipts only. Do not start a metrics daemon, benchmark, new worker or research.

|---|---|

Separate required new-state machine guards, independent review judgment and reserved spot-checks.
