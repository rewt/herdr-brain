The module is a finite foreground CLI and library using Node built-ins. It runs
new commands in a separate process group, forwards INT/TERM/HUP, and retains the
lock while an orphaned command group remains. Known-stale takeover serializes
removers and rechecks the record under its guard. Nested runs neither wait on
themselves nor release the containing run; stale tokens do not authorize nesting.

The migration regression holds a legacy slot, refuses and queues a configured
workspace run, then proves that run holds both records with the same token and
command group. A legacy taker is refused until that configured run exits. Lane
integration tests execute two promotion checks in distinct Git projects against
one slot and prove the second command cannot start before the first releases;
the first command also executes a nested slot command successfully.

Release takes the slot before cutting or claiming a candidate. Contention leaves
no tag, test execution or candidate claim, and a subsequent attempt can proceed.
Its synchronous adapter carries explicit signal metadata across the wrapper so
interrupted gates retain their existing record semantics. Timeout retry logs
contain both attempts and the retry marker; signals, ordinary failures, slot
refusals and second timeouts cannot cause another retry.

Documentation and installed entry policy describe the wait/refusal and timeout
rules for adopters. The record core remains unchanged and dependency-free. No
live acceptance harness or model was called. The bch-cloak checkout was read
only. The final lane check is deliberately the last work command after this
report is checked and committed.
