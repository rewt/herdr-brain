## Five findings

1. **Caller watch cost.** The 100 ms watch now uses `process.ppid` and a
   signal-zero probe. The caller's start/birth record is captured once by the
   adapter. A direct child is reparented when its caller dies, before that PID
   can be reused. Unknown probe errors alone do not trigger a signal. The live
   caller regression instruments both synchronous spawns and hashes after the
   gate's group identity is recorded; it observes neither operation during ten
   polling intervals. Existing top-level/nested caller-death probes still pass.
2. **Direct refusal compatibility.** `runTestSlotSync` catches caller identity
   failures and returns status 75, a coded `TEST_SLOT_HOLDER_UNKNOWN` diagnostic,
   and no attempts or execution evidence. Stderr follows the requested pipe,
   inherited stream or file descriptor, including validation's log descriptor.
   New direct-check and direct-promote probes deny only the caller identity
   lookup once. Both refuse with 75, execute no gate, create no reusable receipt
   and leave main unchanged. Both failed before the fix with exit 1.
3. **Real timeout evidence.** The two timeout probes now call
   `runTestSlotSync` with a real `timeout` and `killSignal: 'SIGTERM'`. They assert
   `ETIMEDOUT`, prove the leaf was running, and read its signal receipt. Both
   top-level and nested compound descendants receive SIGTERM. No manual signal
   substitutes for a timeout in these cases. This corrects the earlier report's
   delayed-cancel evidence; it adds no new timeout policy to the train.
4. **Profile timing.** `gate_profiles[].time_s` again uses the same completed
   gates as summary `gate_time_s`. Separate `executed_time_s` includes measured
   interruptions, matching summary `executed_gate_time_s`; `gates` continues to
   count executions. The regression covers green/red completions, interruptions,
   unfinished starts, cache reuse, duplicate evidence and two command profiles.
5. **Concurrent log proof.** Two concurrently launched callers now share the
   same committed tree, command and cache key, and both execute red gates. If
   the cache-key lock refuses one caller, the test retries it after both have
   finished. It asserts distinct retained logs, complete caller-specific output
   and hashes, with no mutual-overlap timing assertion. In an isolated archive
   of cfd64b6 with only `lanes/validation.mjs` restored from 27e63f3, the final
   probe fails specifically because both receipts name the same overwritten
   `key.log`. This is recorded in `red-concurrent-logs.tap`.
