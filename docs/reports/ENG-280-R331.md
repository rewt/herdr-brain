`waitingImpact` in `lib/state.mjs` counts unresolved dependents once through
dependency diamonds and stops traversal at resolved items. Open runs on these
dependents contribute separately. Current blocked/needs-human reports contribute
when linked or when their blockers name the question; newer active runs,
superseded reports, abandoned runs, and reopened outcomes do not retain obsolete
waiting-report impact. Each question sorts by the total, then creation timestamp,
then creation sequence for an exact tie. Question priority is no longer a sort key.

Plan notes use `Plan:` or a Markdown `Plan` heading, followed by numbered or
bulleted steps naming the question ID. Only the latest marked plan per target
contributes; checked `[x]` steps, completed targets, and ordinary prose are
excluded. The existing folded note kind `plan` is also recognized. The README
documents these conventions and the additive JSON fields: `blocked_count`,
`blocked_work` (`items`, `runs`, `plan_steps`), and `parked`. No stored status or
new event type was added.

Parking starts strictly after 7 * 24 elapsed hours, so exactly seven days remains
visible. The default JSON contains all questions in impact order, allowing the
console to expand its aged fold. `record today --parked`, including with `--json`,
lists aged questions. Reading any of these views leaves the event log unchanged.
Console stage and saved-result folds retain their existing behavior.
