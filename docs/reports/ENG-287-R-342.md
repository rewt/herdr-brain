Dispatch catches failures in timing reads, appends and persistence separately.
Diagnostic failures also cannot replace the wait result or error. Timing failures
increment `timing_missing` in the existing request journal with a fixed stderr
diagnostic, without serializing arbitrary errors or writing the event log
directly. Successful record writes update the local comparison value; retries
seed it from the run metadata already read, so unchanged clocks cause no write.

Watch saves a process-end observation with a valid terminal report, or after its
startup and idle report grace handling permits a terminal notice. The most
recent observed working timestamp distinguishes resumed attempts. A later
terminal decision updates the metadata and appends its new clock; a lost record
reply replays the latest eligible journal clock rather than the superseded idle
clock. The metrics description and module guides now describe this behavior.

Regression coverage compares successful dispatch with and without failing
timing record sets, verifies explicit missing measurement counts, preserves
the stopped result and exact STOP reason during a real simulated memory wait,
and checks that recovery adds no unchanged timing writes. Helper tests preserve
both STOP and other original errors through persistence, journal and diagnostic
failures. Real offline watcher fixtures exercise working, idle, working, done
with idle grace both enabled and disabled, including replacement of an already
recorded idle end. The existing synthetic leak-control and train metrics tests
also pass.

The initial direct node test invocation lacked the repository's suite-owner
environment. The first run through the correct fixture runner passed every
test but identified a surviving watcher because the new tracing wrapper changed
its expected cleanup command. Restricting that wrapper to the new timing tests
fixed the fixture; the final run passed all 66 cases and the ownership audit.
