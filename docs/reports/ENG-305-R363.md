ENG-297 added herdr-read to discovery/install.mjs and herdr/entry-install.mjs,
but omitted it from the recovery allowlist in herdr/entry-transaction.mjs.
Every interrupted plan containing the wrapper was therefore rejected as an
invalid or older receipt before recovery could reverse any changes. This
explains all four failures, including the native settings written before the
adapters and the owned .runtime-<token>.tmp directory created before any wrapper.

The fix adds only the managed wrapper name to recovery validation. Runtime
token naming and ownership cleanup already match, and native settings belong
in the same transaction with their existing write order. The intervening
discovery/runtime.mjs changes concern lane validation/host-suite dispatch and
do not change this machine-install recovery path.

The four reported tests are unchanged. Six added cases interrupt immediately
after herdr-read is written or removed, using either an exception or process
termination followed by --recover. They verify original native configuration
and malformed UTF-8 shell bytes, modes, every installed wrapper and receipt,
retention of prior runtimes, removal of new runtimes/staging, lock/journal
cleanup and idempotent recovery.

Full validation used the bounded offline runner outside the nested worker
sandbox through approved escalation, with private fake sockets and isolated
fixture state:

```sh
node test/helpers/run.mjs test/plugin-install.test.mjs test/zero-setup-install.test.mjs discovery/test/herdr-read.test.mjs discovery/test/entry.test.mjs
```

Result: 90 passed, zero failed, one skipped optional native Claude probe.
Both installer files ran in full; ENG-297's selected machine installer and
plugin lifecycle cases are included, and discovery/test/entry.test.mjs ran
in full. git diff --check passed before the implementation commit.
No model, live Herdr pane, host test slot, promotion/release tier or live
acceptance harness was used.

After report validation and commit, the final action is:
