The module discovers the canonical project from any worktree and uses only the
record CLI for record writes. Receipts and report/diff snapshots live under the
discovered record's `settle/` directory. A per-project/lane lock prevents parallel
settlements. Retries preserve uncertain reviews and recover the single matching
dispatch journal; they never silently launch another reviewer or correction.
Saved promotion readiness is checked again against current Git and record truth.

The offline cycle begins with a false claim: the report says `work.txt` contains
`correct`, while its diff contains `wrong`. A scripted independent reviewer reads
the actual file and emits a schema-validated NEEDS-WORK finding. Actual dispatch
starts a different run on the same item and lane, actual watch delivers its new
report, and the second settle returns PASS and promotion readiness with a clean
tree and green validation. The fixture has no route or lifecycle config, and
the standalone harness retains receipts, logs, snapshots and transport calls in
its JSON evidence. This proves coordination and default behavior; it does not
prove model review quality or real Herdr PTY behavior.

Additional offline cases cover immutable re-ingestion without duplicate proposals,
dirty/foreign worktrees, non-done reports, malformed and uncertain reviews,
uncertain correction delivery and explicit dispatch recovery, red validation
despite PASS, unverified claims, stale heads, concurrent contenders, other-item
work on the lane, dropped items and stale record readiness.

The complete offline suite passed before rebase with 409 passing cases and two
