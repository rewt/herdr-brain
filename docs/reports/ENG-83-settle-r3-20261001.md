Both findings were accepted and fixed; none is disputed. The supplied private
findings were not copied into the repository. The existing public round-two
review was committed without alteration.

The Major regression records an older done report, then records a newer report
with needs_human, blocked, done or failed on the same item. Each case is exercised
with correct and incorrect code. Settling the older run returns a handoff,
preserves the exact outcome and derived status, and launches no reviewer or
correction. Further cases cover an unrecorded stale report, cached readiness,
uncertain review retry and a newer report arriving during PASS or NEEDS-WORK
review.

Interleaving adapters introduce a newer report immediately before ingest, reopen
and correction creation. The record checks the requested run while holding the
transaction lock, so the newer outcome and any explicit closure survive.
Conditional reopen also preserves an outcome belonging to another run and keeps
an already-open retry as a no-op. A legacy incomplete creation journal receives
the same origin constraint before retrying record start.

The Moderate regression stops dispatch at watcher startup after its correction
run has been recorded, then adds an unresolved blocker. The item still derives
active, but retry returns a handoff without re-arming the watcher or sending a
worker prompt. The same holds for a declined question whose status is done.
A resolved linked blocker permits recovery of the existing correction with one
prompt and no additional worker launch.

The original round-two implementation failed both selected regressions in a
scratch source copy: the older report returned promotable instead of a handoff,
and the blocked incomplete retry returned fix_round instead of a handoff. Those
expected failure logs remain outside the repository; the scratch source copy was
cleaned afterward.

The lane was rebased first onto main's entry settings, then again after the
promotion, console and public-review work landed, after priorities landed, and
after the latest acceptance changes. Conflicts in package.json and discovery/policy.mjs were resolved by
retaining both module test groups and both supervisor workflows. The
priority rebase preserved main's test actors and priority validation alongside
watcher cleanup and settlement's transaction guards in record start and dispatch.
The acceptance rebase uses main's child-process cleanup and registers settlement
in its stable case catalog alongside the default supervisor cycle and promotion
queue. Lane code and tests did not change in this last rebase; the passing lane
suite therefore still covers their final contents.
