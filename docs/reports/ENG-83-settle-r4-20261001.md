Both findings were accepted and fixed. The supplied private findings file was
not copied into the repository. The public round-three review already present
in the lane was committed unchanged.

The Major regression abandons the requested run through the actual record CLI
after settlement's initial read and immediately before ingestion. The actual
ingest command returns zero without recording its report. Settlement now hands
off before reopening, validation, review or correction. The same regression
group covers a successful adapter response without ingestion and ingestion of
a different valid report. Each scenario runs with correct and incorrect code;
the item outcome, derived status, run list and lane HEAD remain intact, and no
reviewer or worker starts. The record actor assertion also confirms that the
fixture's explicit actor reached the CLI.

The Moderate regression lets the actual record start succeed, discards its
successful response, and observes a matching dispatch journal at starting with
run null. Settlement retry identifies the already recorded correction and
delegates recovery to dispatch. The result is that same correction run, exactly
one worker launch and one work prompt. A subsequent settlement retry returns
the same receipt without another run, launch or prompt.

Additional lost-response cases retain explicit closure, dropped status,
unresolved links, declined questions whose status is done, and a newer reported
needs_human outcome. The unresolved dependencies are checked even though the
open correction makes the item derive active. Two runs linked to the same
request produce an uncertainty handoff without launching work.

Before the production change, the two selected regressions failed as expected:
the abandoned report returned promotable, and the lost successful start returned
escalate instead of fix_round. After the fix, all four new groups passed, covering
thirteen scenario variants plus repeated receipt adoption.
