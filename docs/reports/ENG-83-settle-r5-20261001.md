Both findings were accepted and fixed. The supplied private findings file was
not copied into the repository. The existing public review was committed unchanged.

The settings-only regression creates a tracked .lane.json containing just the
settle object, with no parent routing configuration. Correct work now receives
PASS and promotable with green validation and no correction. Its saved review
snapshot contains the effective preset routes and excludes settle settings.
Before the fix, the same scenario could not complete independent review.

The relative-config regression selects a file present only in the canonical
checkout, using a path with spaces. The linked worktree has no corresponding
file. Both validation gates execute the selected custom command, review passes,
and the item retains exactly one run. Before the fix, this scenario returned
fix_round for correct work because validation looked up the file in the lane.

Further regressions interrupt a review and retry from a nested directory in the
linked checkout. A conflicting same-named lane config and a changed ambient
LANE_CONFIG cannot replace the saved absolute selection. The retry uses the
original reviewer model and routing snapshot, passes final validation and starts
no correction. Another case starts intake outside the selected --repo directory
and proves resolution is relative to the invoking directory. An unconfigured
retry retains discovery even when its new invocation sets LANE_CONFIG.

The lane review regression supplies a relative --route-config containing a
distinct reviewer route plus unrelated lifecycle values. Review launches that
model while retaining the project's actual main branch. It does not replace
the project's configuration with the snapshot.
