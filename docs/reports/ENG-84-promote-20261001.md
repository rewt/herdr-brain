The implementation commit is **Add ordered promotion queue with durable outcomes
and shared Git locking**. The report commit is **Report promotion queue
implementation and offline validation**.

`node promote/promote.mjs FIRST SECOND` enqueues topics and acknowledges its
worker. Defaults need no `.promote.json`, `.lane.json` or record. Requests retain
supervisor and gate overrides independently. The queue preserves logs, receipts,
refusal reasons, interrupted attempts and exhausted delivery messages separately
from the record's event log. `--status` exposes this evidence; `--drain` resumes
pending requests after stale-lock inspection. A completed outcome awaiting
acknowledgement is delivered without repeating Git; a crash in the delivery
acknowledgement window may duplicate its notice with the same request ID.

Thirteen offline promotion cases cover default FIFO promotion, dirty/red/conflict
refusal with continuation, delivery exhaustion, duplicate pending topics,
overrides, overlapping enqueues, direct-lock exclusion, empty-worker handoff,
interrupted and completed-attempt recovery, stale locks, post-gate mutation, and
record-authorized cleanup that preserves operator and unrelated tabs. The final
housekeeping fixture run passed all 57 cases. The lane suite passed all 146.
The native full npm suite passed 413 with two existing skips; all 27 offline
acceptance boundary cases passed with native socket and sandbox permissions.

Baseline `npm test` was started before edits, then stalled in existing watcher
fixtures under concurrent host load; only that baseline process tree and its
scratch children were stopped. A later restricted full run had two existing
three-second watcher timeouts, and the restricted acceptance boundary run could
not create Unix sockets or nested native sandboxes. Their logs are retained above.
Native reruns passed without weakening assertions or changing watcher behavior.
No model or live operator pane was used for these checks.

The added release-harness case uses a fresh project with no lane/promotion
configuration or record, promotes two lanes through their default npm gates,
keeps a dirty refused lane, and requires ordered delivery of all three notices to
its already-owned supervisor PTY. It retains queue and gate logs in its scratch
evidence directory. Real release acceptance and bch-cloak cutover remain the
existing release gate's work; this run did not execute them. Protected workspace
shells and chats deliberately remain after git-only lane closure. Queue logs and
results currently have no retention policy.
