The fix commit is **Prevent interrupted promotion replay and serialize lane
closure**. The report commit is **Report promotion queue review fixes and
regression evidence**. The lane was rebased onto main before baseline validation.
The supervisor-designated scratch findings file was read in place; both findings
were accepted and addressed.

The crash regression reaches the actual `promoted` checkpoint through the real
lane CLI, pauses the cleanup adapter, captures the saved state and kills only its
own worker and adapter processes. After stale-lock removal in that isolated
fixture, recovery of a checkpoint carrying the older `fresh` flag emits an
interrupted notice. It does not rerun the gate or remove the lane. The gate
receipt remains exactly one entry, the promoted branch tip remains unchanged,
and the worktree remains present.

The concurrency regression pauses queued cleanup after its fast-forward, starts
a real direct promotion of the same topic and pauses that validation. Queued
closure then refuses the shared lock, records and delivers its closure warning,
and leaves the worktree and branch intact. An explicit direct close also refuses
while that gate is active. Releasing the direct gate lets it finish green.
A third regression verifies conditional closure refuses a changed tip and an
unmerged tip without deleting or archiving them, then succeeds once that exact
tip is contained in the base. Existing ordinary archive recovery remains covered
by the full lane suite.

The three added regression cases failed against the reviewed implementation
before the fixes. All 16 promotion cases now pass. Baseline npm validation passed
424 tests with two existing skips, and baseline lane validation passed all 146.
After the fixes, npm passed 427 with the same two skips and the lane suite passed
all 146. Full suites used native execution with scratch repositories and fake
Herdr; they did not call a model or address live panes. The final lane check uses
the same complete npm test set with two files at a time to avoid the watcher
fixture timing stalls observed in the earlier run. Its gate is written after
this report is checked and committed.

Record check also issued an advisory category review because the design rationale
