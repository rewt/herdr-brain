## Findings
- [Moderate] supervisor/request.mjs:16 - The identity request helper appends \`--json\` to every Herdr call, including \`agent prompt NAME TEXT --json\`. The installed Herdr usage text is \`herdr agent prompt \<target\> \<text\> \[--wait\] \[--until STATUS\]... \[--timeout MS\]\` with no \`--json\` option. No other product Herdr caller passes \`--json\`: dispatch, supervisor/chats.mjs herdrCommand and contrib/settle-watch.mjs parse the default JSON output. The fake Herdr in supervisor/test/request.test.mjs accepts any argv, and line 32 of that test pins the suffix. A live delivery can therefore start the desk and then fail at the final prompt step, so the item 4 delivery claim is unproven; Fix: drop the \`--json\` suffix and parse Herdr's default JSON output like supervisor/chats.mjs. Update the test to expect \`\['agent','prompt','desk-bastian',text\]\` and make the fake Herdr reject unknown options so the argv shape is enforced.
- [Minor] supervisor/request.mjs:35 - \`agent start\` gets a spawn timeout equal to the \`--timeout\` it passes to Herdr, so the client is killed at the moment Herdr would report readiness or a timeout. supervisor/chats.mjs adds a 10 s margin. One 30 s deadline also covers agent list, workspace create, pane list, start and readiness polling, which leaves Codex less than Herdr's default 30000 ms readiness window. A slow but successful start reports failure; Fix: give agent start its own startup budget, for example 30000 ms as supervisor/chats.mjs uses, with a spawn timeout of startup plus 10000 ms, then poll readiness against a separate deadline.
- [Minor] lanes/lane.mjs:2325 - The refusal still says release gates are run by the release module, and lanes/README.md line 67 still says the release module owns the declared release command. This change removed that module. herdr/release.sh now hard-codes \`npm run test:release\` and ignores both the declared \`release\` tier in .lane.validation.json and its 7200 s timeout; Fix: point the message and the README paragraph at \`bash herdr/release.sh build TAG\` and update the matching expectation in lanes/test/validation.test.mjs. Then either have release.sh run the declared release tier or state that the declaration is informational.
- [Minor] herdr/README.md:36 - The rewrite removes the concrete one-time cleanup steps that earlier releases documented for machines with entry wrappers, shell PATH blocks and native SessionStart hook groups. Only a sentence saying cleanup is an operator task remains, with no pointer to those steps, although such hooks can interrupt unattended workers; Fix: restore the cleanup paragraph, or link to it at a Git revision, beside the older-installations note.
- [Minor] test/bch-cloak-contract.test.mjs:82 - The contract test passes route, lane, agent, pane, dispatch\_token, start\_head and start\_branch through \`--meta\` but never asserts them on the run.started event. The external consumer contract lists those meta keys along with the item.added title and note.added text fields. Only harness, model and effort are checked, and only through show --json; Fix: assert each listed meta key and value on the run.started event, plus title on item.added and text on note.added.
- [Minor] test/release.test.mjs:105 - The test is named to cover inspecting and switching launchers from an installed release without Git metadata but runs only \`status\`. Activate and rollback from the installed copy are never exercised; Fix: run activate and rollback through the installed release script with HERDR\_MONITOR\_REPO empty, or rename the test to cover status only.
