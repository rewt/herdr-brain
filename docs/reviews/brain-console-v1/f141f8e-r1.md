## Findings
- [Moderate] console/lib/frame.mjs:208 - The approve and decline prompt footer is clipped from its end, so with a long question title the typed decline reason, its cursor and the Enter and Esc hint are cut off (a 48-character title already hides the whole reason at 80 columns, and many pilot titles are longer than the 57-cell list column at 100 columns); Fix: build the prompt from parts in the frame and clip only the title so the reason, cursor and \`Enter to confirm, Esc to cancel\` always fit (or move the title to the status line), and add an 80-column test with a 60-character title for both the reason and confirm modes.
- [Moderate] console/lib/controller.mjs:87 - Overrule always records \`no\`: pressing n on an automatic or agent answer of \`no\` re-records \`no\` with \`--overrule\`, which sets overruled=true and answered\_by=human without changing the answer and inflates the overruled count the operator uses before relaxing a category, and such an answer can never be flipped to \`yes\` from the console; Fix: make the overrule answer the opposite of the recorded one (yes for a recorded no, no otherwise) and name it in the prompt, make \`org answer --overrule\` in bin/org.mjs refuse an overrule whose answer equals the current one, and test both.
- [Minor] lib/render.mjs:269 - The brief's Blockers section, and the \`blocked by:\` line of \`org show\` at lib/render.mjs:358, print a question answered \`no\` as plain \`done\`, so a worker or executive reading them sees the gate as passed while the item is still blocked by the decline; Fix: use isDeclined or blockReason there to print \`declined (answered no)\` and add brief and show assertions to the declined-question test.
- [Minor] bin/org.mjs:241 - normalizeAnswer recognises only a bare yes or no, so \`org answer \<ID\> "No."\` or \`"no, not yet"\` is stored as a text answer and releases the work the question blocks; Fix: treat a reply whose first word is yes or no (ignoring trailing punctuation) as that answer with the remainder kept as the note, or refuse such replies, and add a test.
- [Minor] console/lib/text.mjs:36 - Agent-written text (titles, notes, memos, reports and transcript messages) reaches Ink without control-character filtering; Ink 6.8 strips cursor movement but keeps SGR and OSC sequences, so content can recolour or conceal parts of the approval screen, emit color under NO\_COLOR, pass OSC writes to the terminal and skew the cell-width budgets; Fix: strip ESC sequences and other C0 and C1 control characters from every displayed string in one place (for example in clip and wrap, or on each frame line before rendering) and add a test.
- [Minor] console/lib/cli.mjs:37 - The decline reason is passed as a separate argument after \`--note\`, and strict parseArgs refuses an option value that starts with a dash, so a reason such as \`- not now\` or \`--later\` is rejected with \`Option '--note' argument is ambiguous\` and nothing is recorded; Fix: pass the note as the single argument \`--note=\<reason\>\` and cover a dash-leading reason in the session test.
- [Minor] console/lib/session.mjs:236 - Pressing o on a text document writes a predictable file name in os.tmpdir() with default permissions, follows any existing symlink at that name and never removes the file; Fix: create the file inside fs.mkdtempSync with mode 0o600 and flag wx, and remove it after the blocking editor returns.
- [Minor] console/lib/sources.mjs:85 - Transcript reads are synchronous whole-file reads on the UI process, and each refresh rescans every transcript modified today in the project folder for any ledger name not yet found, so every active and often multi-megabyte transcript is re-read on each refresh; Fix: cache the agent name per file once seen, read only the file tail for the last assistant message, stop rescanning for names known to be missing until the folder changes, and keep these reads off the render path.
- [Minor] console/app.mjs:153 - The app renders one row fewer than the terminal, so a terminal of exactly 80x20 shows the resize hint although the spec shows it only below 80x20; Fix: apply the minimum-size check to the real terminal size, or pass the reserved row to renderFrame separately.
- [Minor] console/lib/sources.mjs:172 - firstMarkdownPath also accepts home-relative paths that start with a tilde, but nothing expands the tilde, so such a decision note shows \`file not found\` instead of its document; Fix: expand the leading tilde with os.homedir() when resolving the document path, or accept only absolute paths as the spec says.
