New issue, finding 1: the hardening was applied to the shared core helpers rather than only to agent-writable paths. absolute() only rewrites the macOS tmp, var and etc aliases, which matches the test environment (os.tmpdir under var folders, and the tests use private tmp directly). On main, loadEvents and readConfig used readFileSync and followed symlinks, so an ORG_DIR through a symlink worked. Now inDirectory opens each component with O_RDONLY|O_DIRECTORY|O_NOFOLLOW, which returns ELOOP for a symlink component. findOrgDir returns path.resolve(ORG_DIR) without realpath, so the path is used as given. Git-discovered paths are realpathed by gitProject, so the default discovery path on this machine is unaffected; on this machine I found no symlink in the shared record path or the parent .lane.json, so the current operator setup does not break, but the product is meant for any project, and modern macOS cloud folders and some Linux distributions with a symlinked home put symlinks in ordinary user paths. Also readPlainFile requires read permission on every ancestor directory (it opens each with O_RDONLY), where plain open only needed search permission; execute-only ancestors would now fail too. And inDirectory calls process.cwd() first, which throws if the calling process's cwd was deleted, a new failure mode for long-running readers; I did not raise these separately.

Finding 4 is operational: freshInteractive returns true for a plain interactive codex typed in the canonical checkout outside Herdr panes; createEntry then adds a worktree before any start. The README says worktrees survive interruption by design, which is right for lanes with work, but empty lanes have nothing to preserve. If createEntry throws after the worktree add (for example runtime dir or metadata creation), entry is undefined and the shim falls back to native, also leaving the lane.
