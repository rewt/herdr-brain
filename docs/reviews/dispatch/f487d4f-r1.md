## Findings
- [Minor] dispatch/dispatch.mjs:148 - Any failure of \`record start\`, including a deterministic record refusal that created no run, leaves the request at stage \`starting\`; \`--retry\` then refuses and \`--recover-run\` cannot succeed because no run carries the journal, so the request is stranded and the caller must hand-search the record and open a new request; Fix: on retry at \`starting\`, look up runs whose \`meta.dispatch\_journal\` equals this journal, adopt the single match automatically, and reset to \`start\` when none exists and the earlier start exited with a record refusal, keeping \`--recover-run\` only for a truly unknown outcome.
- [Minor] dispatch/dispatch.mjs:109 - The item preflight uses \`record show\`, which also resolves run IDs, so \`dispatch.mjs R-5 ...\` passes validation, opens and prepares the lane, and only then fails at \`record start\` with an unknown item, landing in the stranded \`starting\` state above; Fix: require the shown object to be an item (for example refuse when the JSON carries a run-only field such as \`item\` or \`brief\_path\`) before opening the lane, and add a test for a run ID passed as ITEM.
- [Minor] dispatch/dispatch.mjs:97 - \`--retry\` reads the journal before \`lockJob\` runs at line 129, and stale-lock takeover is unlink-then-create, so two concurrent retries after a crash can both acquire the lock (the second unlinks the first lock) or one can proceed with a stage read before the previous holder finished, replaying a launch or prompt that the README says the PID lock serializes; Fix: acquire the lock before reading the journal and re-read the job under the lock, and take over a dead-owner lock atomically (for example write a temporary PID file and rename it over the stale lock only after re-checking its content).
- [Minor] dispatch/dispatch.mjs:175 - \`--reuse\` checks item, lane, route, declared routing and live occupant identity but not that the prior run is reported or abandoned, so reusing a worker whose prior run is still open leaves that run and its live watcher attached to the same worker, producing two open runs on one worker and later no-report notices for the old run; Fix: refuse reuse unless the prior run has a report or is abandoned, and add a test for an open prior run.
