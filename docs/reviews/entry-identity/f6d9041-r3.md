## Findings
- [Moderate] supervisor/session-hooks.mjs:10 - The new passthrough environment also disables interactive supervisor resume. Both automatic adapters route resume commands here, so \`claude --resume\`, \`claude --continue\`, and \`codex resume\` receive worker role and entry bypass. The session hook then skips a valid durable supervisor receipt, preventing cold start and recovery even when a native hook is available; Fix: distinguish interactive resume from utility and headless passthrough, preserve supervisor receipt recognition for interactive resume while retaining explicit worker guards, and cover both adapters with resume-through-adapter tests alongside the headless cases.
- [Moderate] dispatch/dispatch.mjs:308 - Linux watcher identities are decimal start-tick strings, but \`record set\` coerces numeric values into numbers. This write and the equivalent entry recovery write therefore persist a numeric \`watcher\_identity\`, which \`ownerAlive\` rejects as missing whenever the PID exists. A reused Linux watcher PID cannot be compared with its recorded birth and is not re-armed; Fix: persist an unambiguously textual identity consistently across receipts, record metadata, and readers, and add a Linux identity round-trip test through the record CLI that covers both matching and changed births.
- [Moderate] lib/process-owner.mjs:4 - The durable owner reader uses the Linux source's boot-relative start ticks without a boot identifier. If a PID is reused at the same tick value after reboot, an old housekeeping owner or watcher lock compares equal to the unrelated new process, so recovery still reports the dead owner as alive; Fix: include a validated Linux boot UUID in the persisted identity and its live comparison, report an unreadable boot identity as unknown, and test identical PID and tick values across different boots.
