## Findings
- [Major] test/helpers/fixture-lifetime.c:39 - in --watch mode the guard takes its owner from getppid() at its own startup instead of from the process that spawned it; the preload spawns a --watch guard asynchronously from every Node process in a gate tree, including short-lived ones such as \`node -e\` or \`node prep.cjs\`, so if that parent exits before the guard is scheduled the guard is already reparented and records the reaper (launchd as pid 1 on macOS, or a same-user subreaper such as systemd --user on Linux) as its owner, every later getppid() check then passes, and at writer EOF or the deadline it sends SIGKILL to that reaper, a process the test did not start; on macOS as a non-root user the kill fails with EPERM, but this still violates the stated never-signal-a-foreign-process requirement and report claim 1, and on Linux with a subreaper it would kill the user service manager; Fix: pass the spawning process pid on the command line (process.pid from fixture-lifetime.mjs line 111), have main exit 0 immediately when getppid() differs from that argument, and use the argument rather than getppid() as the owner, optionally adding a regression that spawns the guard from a parent which exits at once and asserts the guard exits without signalling
- [Minor] test/helpers/fixture-lifetime.mjs:27 - ownFixtureLifetime now runs the system C compiler eagerly in every bounded-test file process and every first fixtureFleet call, with no source-digest cache, so every test file pays a compile and a missing or slow compiler under load becomes an import-time throw for all bounded suites, while the existing pty.mjs nativeOwner already caches its build by source digest; Fix: build once per suite into a digest-keyed cache under the shared offline root, as pty.mjs nativeOwner does, and reuse the binary when present
- [Minor] test/fixture-lifetime.test.mjs:93 - the comment says the direct SIGKILL case runs with no containment preload, but the outer test process has its own lifetime, so its patched ChildProcess spawn re-adds NODE\_OPTIONS with the lifetime preload and the outer lifetime variables to the victim runner even after the test deletes NODE\_OPTIONS; the regression still holds because the victim's own fixtureFleet creates a fresh writer, but the comment misstates what the case exercises; Fix: reword the comment to say the outer preload is inherited and the victim replaces it with its own lifetime, or spawn the victim through the unpatched native spawn if a truly preload-free entry is intended
