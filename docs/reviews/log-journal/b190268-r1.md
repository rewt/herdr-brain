## Findings
- [Moderate] logs/journal.mjs:194 - Retention carries cumulative producer watermarks forever inside one service.retention control, but a stored envelope is capped at 16 KiB, so after roughly 170 distinct pruned producer (id, epoch) pairs (source-gap events use a fresh epoch per gap and shadow producers use per-session epochs) validateEvent at line 200 throws on every retention attempt; retain() then fails permanently, the byte and age ceilings are never enforced again, and because append() calls retain() unconditionally at line 166 every later append rejects after its event is already durable; Fix: bound the watermark state (for example expire watermarks older than the retention horizon, or spread them across several bounded controls or a checkpoint that retention itself preserves), keep retention able to make progress, and add a fixture that prunes more producers than one control can hold.
- [Moderate] logs/inputs.mjs:42 - The record mirror reads a review verdict from source.report.verdict and copies only top-level report fields, but lib/report.mjs:124 stores every non-core frontmatter key (including verdict) under report.extra and lib/state.mjs:289 reads report.extra.verdict, so an ingested NEEDS-WORK or FAIL review report is mirrored without its verdict, routes as triage instead of direct and is invisible to the review-loop rule; the CLI test only passes because its fixture invents a top-level review.verdict record event type that the record vocabulary never writes; Fix: take the verdict (and other typed evidence such as reviewScope) from source.report.extra as state.mjs does, normalize it the same way, and replace the synthetic record type in test/logs-cli.test.mjs with a report.ingested review fixture carrying extra.verdict.
- [Minor] logs/inputs.mjs:28 - The receipts map selects dispatch.receipt, watch.receipt, dispatch.delivery.receipt, watch.observation and review.verdict, none of which the record writes (lib/state.mjs folds run.started, run.updated, report.ingested and similar), so the asked-for watch receipts are never mirrored from a real record even though run.updated meta carries watch evidence such as process\_end, while logs/README.md:179 describes typed dispatch/watch/review receipts as selected; Fix: either mirror the existing run.updated watch metadata into record.watch.receipt evidence, or drop the dead mappings and state in the README that watch receipts are not available from the current record.
- [Minor] logs/journal.mjs:165 - append() reports failure for an event that appendRaw already made durable whenever the post-commit detector or retention pass fails, which happens under ordinary fail-fast contention (another writer holds log-writer.lock) or when the unlocked read at line 153 observes another writer's in-progress line or retention deletion and reports a torn tail or missing file; the producer sees an error instead of its cursor; Fix: return the commit result from append() and surface detector or retention failures separately (for example a followUp error field), or skip the post-commit passes on contention so a later call reconciles them.
- [Minor] logs/journal.mjs:131 - Every append rereads and reparses every retained segment under the writer lock, and append() repeats full reads for detectors and retention, while detect() filters the whole blocker and refusal lists per event; at the adopted 256 MiB retention each append can parse hundreds of MiB several times; Fix: keep a per-instance state rebuilt from the segments at open and revalidated by segment size, or document the per-append full-scan cost as an offline-only limit before the service step.
