# Overnight questions without automatic judge work

ENG-936 retires automatic blocked-work decision creation and review/dispatch
missing-producer decision creation. Their effects journals and cumulative
diagnostics retain actual owner/receipt facts. Fresh starts of rule-generated
review/dispatch decisions and `backlog_batch` items stop; existing saved dispatch
requests may continue only through their original guarded path. Existing typed
requests, claims, UNKNOWN attempts, watchers, archives and reserved questions
remain consumable. No item, history, receipt or attempt is deleted or cleared.

Closeout and source-completion decision generation/admission are unchanged while
ENG-931's proof runs. This source change does not restart services, edit a runtime
or pin, activate a release or adopt anything in another project.

## Answer a real question in the existing supervisor session

The worker first reads available item intent, acceptance and standing decisions.
If information is still missing, send ONE question through the existing PROJECT
SUPERVISOR inbox: item/run, exact question, relevant evidence, recommendation,
affected action and authority boundary. Keep its stable inbox ID and preserve
UNKNOWN delivery or native refusal. No decision item or separate backlog judge.

The supervisor reads the full owning intent and current record. Its reply states
the answer, authority reference, evidence, limits and falsifying observation.
Record the decision note on the existing subject and reply through the existing
worker inbox. The requesting owner freshly checks claim/source/native/HOLD/STOP
before acting. The reply is agent-authored, never an actual human answer.

Apply [decision routing](../supervisor/DECISION-ROUTING.md). Existing delegation
can answer routine technical questions. Missing facts remain unknown. A new
technical contract needs the authorized T2 delegate. Reserved effects require
the actual operator and existing once-only named reserved-question path. No
reply clears a native refusal, identity conflict, dependency or HOLD. Only the
dependent action waits. Unanswered questions never expire into consent.

For example, a question about rerunning the full suite can be answered from the
focused-check direction, naming the affected check. Permission to release cannot
come from general technical delegation. An UNKNOWN original launch needs its
actual owner, never a replacement. A missing receipt is owner reconciliation.

This adapts bounded user-answering research to the already recorded project
supervisor. It adds guidance for future workers, not a resolver/model service or
proof of live overnight success. See [measurement and dated sources](../docs/reports/ENG-936/decision.md).

## Historical captured decision contract

The following contract is retained for original captured work and recovery.
Its automatic creation stage is superseded above. The unchanged prior page is
also archived at docs/reports/ENG-936/decision-loop-prior.md.

The adopted decision-loop is opt-in through an owning Brain worker's native
claim and the exact landed source. Existing services, watcher, inboxes, pins and
saved jobs are retained. Other project identities cannot activate this rollout.

From the current owning lane, after its source lands:

```
node /canonical/herdr-brain/line-service/decisions.mjs --org /own/.org --run OWN_RUN --activate --expected-head FULL_SHA --authority operator-adopted-20261027/decision-loop.md --subject REAL_BLOCKED_ITEM
```

Omit `--subject` only for an explicitly authorized full selected Brain slice.
The source must be clean and integrated; the actual worker and claim are checked
at this effect. `--deactivate` with the same arguments withdraws application
without stopping services. No activation happens just because source lands.

After the existing mechanical rules, the line derives one decision per actual
subject/report/claim/current-intent tuple. Real holds, reserved ancestry and
unselected proposals remain ineligible. It archives the full report, contract,
standing intent and attempt ledger, creates an ordinary `decision` item, and
uses the existing `unblock` route, dispatch journal and a separate one-judge pool.
The native dispatcher and service share that pool and preserve uncertain starts;
full build slots do not consume it. Explicit shared native ceilings remain.
Unknown starts are retained. No code calls a model or runs another loop.

The new role's sole output is its report. `decision` in report front matter is a
mapping with `version: 1`, captured `key`, `action`, `category` and `reason`.
Actions are `reopen`, `reshape` (only `title`/`accept`), `supersede` (exact
`successor`), `park`, and `ask_operator` (`question` and `recommend: yes|no`).
Operator questions are explicitly reserved, block their subject, and enter the
existing once-only Brain Chat pointer. Their eventual actual human answer does
not authorize the service to execute reserved outward effects. Existing native
owners retain those actions. Safety/identity/native holds are never cleared.

Application rechecks current intent, report bytes, both claims, native judge,
original source and STOP/HOLD under the existing record lock and effects intent.
A done judge report does not release its blocker; only a committed applied/stale
disposition can do that. A service-authored `decision.restart` tied to `decision.applied` explicitly
restores ordinary dispatch eligibility; incidental service notes cannot do so.
A stale answer closes only its obsolete decision item. Invalid typed reports
count once, get one configured other-family reframe with an explicit guarded
restart authorization (also for blocked reports), then park. A repeated
same-premise application gets one other-family answer, then stays parked. A
quiet or uncertain native start consumes its original slot; it is never timed
out or replaced. Missing other-family support parks rather than inventing it.

Before superseding, the exact clean source tree and application state are
archived under `.org/evidence/decisions/KEY/`. All unfinished incoming and outgoing
dependencies transfer to the exact selected successor; missing recovery,
reserved/held successors and dependency cycles refuse closure. Closed human refusals and closed failed
reviews remain unresolved prerequisites and transfer too. No source/data is
deleted. Existing guarded closeout owns session retirement and lane archives.

`--restore KEY` in place of `--activate` is a guarded native owner operation on
the archived application. It restores exact subject fields (including absent
metadata) and transferred links only before any consequence or affected later
write. After downstream work starts, use a new intent/decision; reopening alone
cannot undo downstream effects. Source rollback is a normal owning-lane
`git revert` of the reported immutable source range, followed by the affected
checks and expected-head promotion; never edit an installed bundle or pin.

The consumer records consequences separately: actual completed original prompt
and native restarted worker, exact dependency transfer, or a pending reserved
question's actual human answer. A detached acknowledgement is not proof. Final
work success, final-release acceptance and session retirement need their actual
receipts. These records also expose class, premise, family, request/start/applied
latency and repeated blocks for the adopted first-week evaluation. No supervisor
or watcher route is removed before its replacement works in the live project.

This replaces hand relaying reversible answers and hand reopening unchanged
blocked reports for the activated slice. Standing supervisor/release duties,
legacy exception delivery and BCH adoption remain with their actual owners.
