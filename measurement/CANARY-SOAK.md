# Exact-candidate Brain soak handoff

This is a read-only consumer of ENG-1130's `measureLifecycle`. It evaluates saved
inputs once and emits JSON on stdout. It neither polls nor performs any runtime,
record, pin, native, cleanup, release or scheduling effect. A verdict is evidence
for the existing coordinator, never mutation authority.

HUM-43's **30 October 2026 20:19 human answer** approves construction and changes
the earlier design rule: passing installed canary **and** real soak plus landing
tests support consumer offers. Full-suite results, failures and absence are
non-blocking background information. Preserve actual results and fix real bugs
forward. The design's old final-full-suite prerequisite is superseded. Exact
stable live acceptance, specific Major corrections and outward/native activation
checks remain with their existing owners. Fixture greens do not complete a live
trial, grant READY, change a pin or imply consumer consent.

Before a real trial, supervisor-herdr must establish these facts:

1. A compatible accepted **installed previous runtime** with retained manifest,
   installation/plist and original migration/upgrade archive. A development
   checkout or global `current` link alone is not an installed rollback target.
2. One corrected immutable candidate: full source commit/tree, bundle root,
   original manifest and inventory hashes, protocol/config compatibility and
   pinned Node executable/version. Retain relevant producer landing checks and
   specific correction evidence. A2's original failed tuple stays failed.
3. Passing exact-candidate A2 S0–S8/shared-observer packet, plus the supervisor's
   separate operational authority for a safe-boundary Brain-only probation.
   HUM-43 design approval and selection of A4 authorize construction; they do
   not make this worker the canonical runtime executor.

Use [the existing A3 procedure](../line-service/README.md#brain-only-probation-for-one-routine-candidate).
Only the canonical supervisor stops the service, retains its STOP, previews
`probation-authorize`, records its exact required decision, applies the unchanged
plan, previews/applies `upgrade` from the candidate root and separately restarts.
Do not change consumer pins, shared-watch defaults, saved jobs, callbacks or
watchers. In-flight old-root workers retain their captured roots and are reported
as carry-in work, never candidate completions. Existing/UNKNOWN authority or
upgrade attempts remain under their original IDs and owners.

Start the window only after installed controller, new admissions, workers and
watchers have matching provenance. Work may land on moving development main;
captured runtime bytes must remain fixed. No synthetic work, manual starts or
nudge may fill the sample. At least 90 minutes **and** ten useful ordinary units
through cleanup, three source units and two successive capacity turnovers are
required. All project starts after the opening sequence fence are included,
including reviews, failures, late pending runs and unknown provenance. Explicit
line actor sets are required when the real controller uses a supervisor actor;
actor names alone are not proof of automatic initiation. The saved audit and
rescue ledger must establish that distinction. Reviews do not inflate ordinary
counts. A legitimate held resource retains its owner/reason and keeps the offer
pending. Timing targets never authorize kills.

## Saved input contract

Run with pinned Node, from any owned context:

```sh
"$NODE" "$SOURCE/bin/evaluate-canary-soak.mjs" --events events-snapshot.jsonl --trial trial.json > assessment.json
```

Exit 0 means an assessment was produced, including FAIL/INCOMPLETE; exit 1 means
invalid input or artifact verification failure. Never interpret exit 0 as PASS.
The CLI verifies **every** `evidence` file's raw SHA256 before evaluation. Paths
resolve relative to `trial.json`. It loads the original A2 packet and A3 archive
from verified files; inline status/authority copies cannot replace them. Other
observations are the coordinator's saved, reviewable assertions, not new product
events or authenticated native receipts generated by this evaluator. The pure
`evaluateSoak` API expects these hydrated objects and the IDs of already verified
artifacts. It must not be used to bypass file verification.

`trial.json` has `schema: brain.canary-soak-input/v1` and these fields. Every
object described as having proof has `evidence: [ID, ...]` naming the artifact
map. Missing proof is INCOMPLETE. Keep the raw evidence, not just this input.

| Field | Exact content |
| --- | --- |
| `project` | Actual canonical Brain Git common directory. |
| `window` | Explicit UTC `from`, `cutoff`, opening `start_seq`, closing `through_seq`. Snapshot includes earlier events needed for joins. Every input event at or before `cutoff` must have `seq <= through_seq`; every project start in `[from, cutoff]` must have `seq > start_seq`. Violations keep the assessment INCOMPLETE and name the excluded event/start. Freeze all input bytes at that cutoff. |
| `candidate` | A2 tuple: `root`, full `commit`, `tree`, `manifestSha256`, `inventorySha256`, `node: {executable, version}`, `protocol`, `configHome`. Use original bundle, never fixture manifest. |
| `evidence` | Map ID → `{path, sha256}`. Include original manifests, frozen validation, inventory, dispatch journals, runtime/archive snapshots, raw native/Git/record observations and checks. |
| `scripted` | `{packetEvidence: ID}` for original `brain.installed-canary/v1` JSON. Cases S0–S8 and shared-observer, original review and zero suites are mandatory. Original failures cannot be cleared by separate successful corrections. |
| `landing` | Proof, matching `candidate`, named `selection`, `checks: [{command, exitStatus, nodeVersion, appliesTo, evidence}]`. Exit must be 0, Node v20.19.4, `appliesTo` exact candidate commit. An older valid receipt needs explicit saved applicability/reuse analysis; do not fabricate an exact-head run. |
| `probation` | `{archiveEvidence: ID}` for original `brain-probation/v1` archive. The event snapshot must contain matching pre-window authority event and exact canonical-supervisor decision. Archive hash must match that event. |
| `recovery` | Proof, archived previous `root`, `accepted: true`, `compatible: true`. Recheck current-record compatibility through the existing owner before an actual rollback. |
| `controller` | Proof and `samples` at both exact window endpoints (and intervening observations). Each sample: proof, `at`, full `candidate`, `newAdmissions: true`. |

| `rescues` | Proof, `complete: true`, exact `from`/`cutoff`, `actions: []` or every actual action with run/owner/time/reason. Completeness is a saved audit assertion; B4 manual-assistance events alone cannot establish zero rescues. |

Each `runs` entry has proof, `run`, exact `startedSeq`/`claimGeneration`, `kind`
(`ordinary` or `review`, checked against record), and `useful: true` for genuine
ordinary work. `runtime.controller/worker/watcher` each contain proof and the
full candidate tuple copied from saved executable/journal provenance. Include:

- `physical`: proof; `before.session/tab/folder` actual identities matching the
  native binding, closeout tab and run workspace; `after` each `absent`. Save
  before/after native session/tab, Git refs/worktrees and filesystem observations.
  Absence alone is not retirement: B4's typed linked effect receipts must agree.
- `turns`: proof; identical actual `close`, `session`, `folder` finite-turn IDs.
  Supporting evidence must prove source item closure precedes the async verdict.
- `queue`: proof; `eligibleAt`, `freeAt`, `inputAt` (matches the original native
  session binding's `prompted_at`), full native `allocation` and structured
  `freedBy: {type, seq, run, sha256}`. `freeAt` is the original report-ingested
  event time: logical admission release, independent of folder retirement.
  Two successive in-window ordinary links must reuse the exact middle allocation.
  Each unit still needs linked automatic session/tab/folder retirement and
  independent physical absence by cutoff. Removal may follow the next start.
  Roots/reset/carry-in/review links supply no ordinary turnover credit.
- `source` for source-producing work: proof and immutable landed `base`/`head`.
- `review`: proof; source work names its original review `run`, `original: true`,
  `cap: 1`, `suites: 0`. Non-source work can explicitly use `required: false`.
  Review runs retain their original cap/zero-suite proof and passing report
  verdict. A nonpassing original review keeps the offer pending for the existing
  coordinator to reconcile specific checked corrections; this version errs on
  withholding rather than synthesizing a new PASS verdict.
- `shared`: proof; `mode: shared`, `perRunWatcherRssBytes: 0`, measured positive
  `hostRssBytes`, nonnegative `noticeLatencyMs`, `expectedNotices` (positive),
  `deliveredNotices`, `duplicates: 0`. Save actual notice IDs/observation spans.
  The output retains per-run RSS and descriptive notice count/median/p90/max;
  it imposes no invented notice-latency threshold. Missing shared observations
  keep this combined offer pending. This evaluator never switches the default.

## Disposition and later failure

INCOMPLETE: withhold the offer; retain every pending run/resource, owner, reason
and next event. The same authorized trial may continue for genuine demand, never
by replacement of uncertain effects. FAIL: withhold/withdraw the offer even if
the scripted layer passed and ten other units succeeded. The canonical supervisor
contains **new admissions** through supported STOP (or explicit emergency probation withdrawal), preserves
all captured workers/watchers/callbacks/UNKNOWN attempts, and owns recovery.

Stop through the installed controller's normal owner first. Keep the original
trial active while recovering: withdrawing its exception can prevent the sealed
non-READY recovery root from restarting. For this Brain development-recovery
trial, use **canonical Brain source** `probation-successor --rollback`, the
**original trial ID**, current installed successor as `--from-root`, and the
original sealed recovery as `--target-root`. Preview, record its exact required
decision, and apply that unchanged plan under one stable recovery ID as documented
in [the successor rollback procedure](../line-service/PROBATION-SUCCESSOR.md).
Restart through the sealed recovery's own tool, retaining all recovery and clear
receipts. Do not use ordinary `upgrade --rollback` for this bootstrap history.

For a trial entered from an accepted installed predecessor through ordinary
upgrade history, use that candidate's `upgrade --rollback` with reversed roots
and a stable rollback ID, then restart the accepted predecessor separately.
An explicit `probation-withdraw --emergency` on a corrected tool revokes trial
admissions even when no continuation exists; it does not promise a recovery
restart. Use it only for deliberate containment and route the lost continuation
to the supervisor. Ordinary withdraw/complete previews refuse without a READY
explicit project pin selecting the settled installed root. Frozen tools retain
their old behavior; source landing does not patch them.

A global current-link rollback alone does not restore a pinned line. Do not
revert landed source or downgrade incompatible records. Confirm
the prior controller plus a normal eligible start; that is recovery evidence,
not a new candidate PASS.

Blocked/refused/UNKNOWN recovery stops that effect. Preserve its original intent,
receipt, owner and retained work; do not replay, rename, borrow identity, switch
executor, delete held work or clear STOP to force progress. Route the exception
through the owning brief's durable `supervisor/prompt-supervisor.mjs` command to
`supervisor-herdr --project-supervisor` with a stable notice ID, and retain it on
the item/run. Missing bindings stay pending under that original ID.

Both layers PASS plus landing evidence: the release coordinator may assemble
the existing record/callback offer packet. Attach this assessment, frozen inputs,
all artifacts, original attempts, workload/load limitations, unresolved dimensions,
recovery archives and actual stable live/Major/outward status. Each consumer's
own activation owner explicitly accepts, defers or declines through its supported
controls. No other project state is written. One async immutable producer
diff/evidence review follows the existing report queue; no reviewer suites or
parallel settle/review path is introduced.


## Verified capacity and physical debt

`capacity` names `inventoryEvidence`, `configEvidence`, `censusEvidence`,
`complete: true` and `journalRefs: [{journal: ORIGINAL_ABSOLUTE_PATH, evidence: ID}]`.
All IDs resolve saved original JSON bytes through the normal digest-verifying
reader. Inline `saved`, allocation/config overrides and live journals cannot
replace those bytes. The inventory has `complete: true` and the complete original
`journals` path list, including ancestors and sibling allocations. The config
packet has `identities` containing saved configured `capacityIdentity` values
(project, record, pool, cap and cap provenance). The census has `complete: true`,
`at: window.from`, `through_seq: window.start_seq` and `resources`; each carry-in
row retains `run`, `allocation` ID, exact `capacity`, `startedAt` and observed
`session/tab/folder` states (`present`, `absent` or `unknown`). Unknown origin,
identity, pool, inventory or retirement coverage withholds a complete audit.

The adapter parses only hash-verified original jobs. The shared native
`validateCapacityAllocation` validates receipt hashes, start/claim/journal and
attempt bindings, admission fences, original report release and full ancestor /
sibling consumption. The queue must equal that original receipt, including all
release fields. Release sequence precedes the next start and wall time is no
later for turnover credit; equal timestamps use event sequence. A valid release
selected after the start can establish admission without earning turnover.

`capacity` output separates each exact pool's physical run occupancy from
report-released/unretired debt. Both retain opening/peak/cutoff counts and cap
ratios, run/allocation IDs, known oldest ages and per-resource endpoints; debt
also records created/resolved counts. Carry-in/held/failed/review resources stay
visible. Unknown coverage marks the peak as a lower bound. Physical overlap
above a logical cap is descriptive; an actual logical over-admission remains
adverse. Directory absence alone proves no retirement timestamp.
