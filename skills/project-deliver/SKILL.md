# Deliver owned work

Use the assigned project's AGENTS.md, ask, run brief, record and pinned runtime.
Resolve its actual Git common directory and native claim before a mutation.
Shared instructions never authorize cross-project edits or another worker's
source. BCH files and actions stay with BCH identities.

Finish and commit only the authorized source in the owned checkout. Keep durable
evidence outside disposable lane folders. Run the selected focused checks once
on the clean committed candidate through the project's existing runner/lane check;
for Brain the brief's pinned Node invokes `lanes/lane.mjs check --cmd 'COMMAND'`.
Inherit its actual command, exit, TAP totals, runtime and receipt. Preserve failures;
after a fix run only failing, affected or unrun controls. Never substitute a
default suite, manufacture a gate or describe unrun checks as PASS.

Under the current land-first waiver, self-land finished OWN source through the
project's existing guarded lane command before reporting. For Brain:

```sh
node lanes/lane.mjs promote TOPIC --expected-head FULL_SHA
```

Here `node` means the pinned runtime and source root specified by the brief.
Use BCH's own supported entry under its identity rather than importing this
Brain-relative command. Clean Git, the actual worktree/common directory, native
identity, claim generation, source ownership, expected head, main CAS/FF and
STOP/HOLD remain enforced. No test, review or report readiness gate is added.
If main moved, rebase in the owned lane, resolve real conflicts, and capture the
new full head before requesting promotion. Protected commands use the prescribed
native approval path. A native refusal stops that effect; an UNKNOWN attempt is
inspected with its original receipt, never replaced or retried blindly.

Record the actual immutable landed base/head and promotion result. Analysis-only
work has no source delivery to invent. Keep any explicitly held source separate
and identify its retained branch/commit without claiming it landed.

Write the run's report using its supplied template and exact run ID; validate it
with that project's `record check`. Include the done condition, actual scope,
decisions, named verifier/evidence, checks and unrun limits. The declared delivered
range artifact for the current Brain queue is `source: HEAD; base: BASE` with full
commit IDs. Distinguish retained/unlanded evidence from that delivered range.

Leave the existing report watcher and its recipient intact. Report ingestion and
the line own the single async queue-review path: cap1, zero reviewer suites. Do
not start settle/lane reviews, wait for a verdict to land, or invoke supervisor
cycle mutations. Ordinary notices use the recorded worker's `--to`; saved review
completion keeps its prompt path. Own a linked correction/fix-forward when assigned.

Operator notices use the owning record's supported `messages send` entry from
the brief: plain headline, what happened, action, then one Details line for codes.
Routine status stays in the record. Only a genuinely pending question explicitly
reserved in the record uses its existing one-time operator push. Actual exceptions
go to the PROJECT SUPERVISOR; no operator-pane typing or borrowed identity.
