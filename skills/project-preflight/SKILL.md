# Scope and allocate work

Read the assigned ask, run brief and active project's AGENTS.md. State a concrete
done condition and the paths/effects excluded by the ask. Reuse recorded decisions
and the producer's existing evidence; do not add another admission checklist.

Bind operations to the assigned project, its real Git common directory, owning
record, active claim and native worker. A display label, chat/session ID or cwd
alone is not authority. Use the project's current source command and pinned
runtime from the brief; never substitute another project's record or identity.

## Choose the workspace

| Work | Source allocation |
| --- | --- |
| Research, planning or record-only work | Existing project context; write durable results to its designated record/evidence location. No new source worktree. |
| Review | Captured commit objects/diff and producer evidence. No new writable source worktree or producer checks. |
| One source writer, with exclusive ownership of its checkout | Reuse that checkout if the project's guarded tooling already supports that binding. A new tree is unnecessary. |
| Source writer alongside another source writer | One isolated worktree per concurrent writer, with an actual project claim. Never share an index or change another writer's tree. |

An existing claimed lane remains owned until the project's supported handoff.
This allocation decision does not migrate a live run, bypass a lane requirement,
or authorize removal of an existing checkout. If current dispatch still allocates
every role a tree, record that limitation for its owner; do not invent a native
binding to make the preferred allocation appear implemented.

Split only independently useful outcomes with separate write surfaces or stable
interfaces. Give a shared interface one owner; sequence dependent edits. Allocate
other agents only when the task and available delegation authorize them. Herdr's
existing skill supplies native controls when requested; do not duplicate its CLI.

Select only the ask's applicable focused checks and any explicitly added scope.
Preserve the project's runner, file groups, limits and known native exclusions.
Name an empty selection as unrun. Full final-release coverage belongs to the
release coordinator; check/review readiness does not gate current self-landing.

Resolve routine implementation choices yourself. Route actual unsafe, native,
identity, ownership, reserved or failed exceptions to the recorded PROJECT
SUPERVISOR. A native refusal stops that effect; preserve it and continue
independent work without changing executor or identity.
Use the owning brief's durable native-inbox entry before input for exceptions,
and retain the exception in the item/run record. Do not substitute a direct
prompt. For Brain, the brief supplies the source command with
`--project-supervisor`, one stable notice ID and the actual project address;
missing bindings remain pending, while refused/uncertain attempts cannot replay.
