# Supervisor protocol

Until the stable release, Brain and BCH implement the same rules in separate tooling; BCH switches to Brain tooling after adopting the next release. The operator steers and routine reversible work remains delegated.

Finished source lands immediately. No pre-main test, merge, affected-file admission or review readiness gate. Red main is accepted and actual failures are fixed forward. The explicit committed landing waiver records executed:false and exit_code:null; unrun tests are never PASS. Preserve native binding, claims, source/head/clean Git/CAS/FF safety, reserved questions and recoverable archives. Real source conflicts and unknown/foreign ownership remain real issues to resolve.

Every item receives exactly ONE independent review AFTER CODE, of immutable diff and evidence only, ASYNC/NONBLOCKING alongside engineers and landing. Cap1 applies prospectively; the approximately30-minute target is planning, never an elapsed stop. Timeout0 is supported and disables the review deadline. Zero reviewer tests/build/install/prepare/check/probe/mutation suites. No pre-code, plan, contract or concurrence stage. At most ONE formal fix round after the review; no automatic second full review or re-review chain. Later findings fix forward. Majors must actually be corrected and their specific correction/evidence checked before FINAL RELEASE. Preserve historical verdicts/caps/receipts.

## Existing delivery and landing

Use existing dispatch/owner/lane/route flows and one normal watcher per run. Do not duplicate workers/watchers or restart schedules. Ordinary report, review and promotion notices return to the owning worker. New dispatches without an explicit --to bind their watcher to the recorded, live-verified worker; explicit recipients and saved retries keep their destination. A bootstrap watcher already targeting the supervisor stays intact. Its supervisor forwards ordinary follow-up to the recorded owner through the existing prompt delivery, without starting another watcher or review. Actual unsafe, native, identity, ownership, reserved or failed exceptions go to that worker's PROJECT SUPERVISOR at its supported project-specific address. Autopilot remains disabled unless independently enabled under its existing authority.

Current-source generated briefs resolve the explicit parent `MONITOR_SUPERVISOR_AGENT` first, then effective project dispatch/route launch env, then the target project's effective `promote.to`. Child-only launch env is resolved as policy; it does not change the parent process environment. If no address can be resolved, the footer states UNKNOWN without inventing a recipient or blocking dispatch. Each identity's owner supplies its actual project supervisor address. Older installed/saved prompts can retain the legacy Brain fallback; source edits change no installed binary/config/pin or saved recipients/watchers/claims.

The finishing engineer lands OWN source immediately through lane promote TOPIC --expected-head FULL_COMMIT under the current operator waiver. Preserve the actual native worker/claim, clean canonical and lane worktrees, clean rebase, source/head/CAS, fast-forward, STOP, HOLD and recoverable archives. If main advanced, resolve/rebase in the same owner and bind the resulting exact source before promotion. A final report is not a pre-main gate: the report-bound --if-current-run form requires recorded intake and is used only when that intake already exists. Never invent a report or borrow supervisor identity to satisfy it. Direct promotion leaves the lane available for its owner's report and closeout. For queued promotion use promote/promote.mjs TOPIC --expected-head FULL_COMMIT --to OWNER_AGENT; keep existing record bindings when applicable. No push, release or synthetic validation-done/full-suite receipt follows.

The worker starts its ONE independent async post-code review itself through the existing lane review route, with --parallel-review --run RUN --captured-head FULL_COMMIT --captured-base BASE_COMMIT --round 1 --timeout 0 and an immutable ask/evidence brief. Start it alongside landing, never wait for its verdict. The existing prompt delivery can return its completion to OWNER_AGENT; report-driven settle uses --to OWNER_AGENT. Retain responsibility for the one formal correction/fix-forward. Review reads captured commit/diff/evidence and runs zero producer suites. Final report intake consumes the existing review binding/status and owner verification receipt once; do not invoke a second settle/review or repeat successful checks/integration. Supervisor handle/promote remain exception/recovery tools, not the routine worker path. Never invoke supervisor cycle mutations from a worker.

Each routine fact has one designated verifier and an evidence locator in the existing report/receipt. Consume that result once. Fresh identity/claim/source/CAS reads at a new mutation boundary remain required. Brain Chat spot-checks reserved/outward permissions, publishing, funds and operator-command boundaries, or a concrete contested exception. Record source-ready, landing and report clocks from actual receipts, including signed source-ready-to-land/report-to-land gaps and land-before-final-report; unknown history stays UNKNOWN and prior comparison cutoffs/denominators stay intact.

Until activation, invoke the changed canonical source explicitly with the pinned Node. For a NEW cold dispatch in a home-bound/pinned project use HERDR_BRAIN_ROOT=/CANONICAL /PINNED/NODE /CANONICAL/dispatch/dispatch.mjs ... without --to. The selector must match the invoked development root; dispatch records its actual root/head before creating a new run. It selects this dispatcher without editing the target/global pin. Without that selector normal project/home forwarding remains. Child CLIs retain their project/claim selection guards; retries and --from-run always retain the original source/release and destination, never adopt old work. Record the actual selected root/head and recipient. A direct source invocation does not update installed current or already-running sessions/watchers. Use only supported policy writers when a bound home-policy default actually needs changing; legacy entry/chat settings have no effect. Never edit an immutable installed bundle or claim that documentation activated a runtime default.

Completion/closeout retain exact native receipts and callback identity. Retry only failed bookkeeping/cleanup after its actual cause is fixed; never repeat successful integration/checks. One requested formal correction may follow the review. An uncertain review is inspected in its existing session, never automatically re-launched. Historical source, failed gates and review verdicts remain immutable.

## Final release/adoption

ONE FULL release test is PER RELEASE and shared by all fixes, immediately before final release/adoption. It is FULL, never reduced, and is not repeated. Preserve completed receipts/greens; after a real correction execute only failing, actually affected or previously unrun checks, binding inherited and fresh coverage honestly to source. Passive step timing measures the next actual final candidate; do not run a separate whole-suite benchmark. Deduplicate executions and parallelize only genuinely independent suites while retaining native/Herdr/focus/shared-state/slot/memory/ownership constraints. Light CPU alone proves no independence.

Zero elapsed-only test/helper/runner/gate failure. The sole forced freeze is the exact measured no-output AND confirmed-no-activity condition; unknown activity stays held. Semantic native leases/claims and ownership/source safety remain enforced.

For a fresh final obligation, tag assembled main and start bash herdr/release.sh build TAG --live as one bare command. A real failure retains that immutable candidate and its completed evidence; do not repeat the whole build command after a correction. Bind the corrected genuine candidate and continue only failing, actually affected or previously unrun checks through the existing runners. Full coverage, actual Major correction checks, genuine source, package/seal and real live acceptance must all be proved before bash herdr/release.sh activate TAG and actual installed org/lane/contrib/reconcile readback. A green coverage component is not a synthetic full-command or validation-done receipt. Workers never release. A new candidate records its actual correction and source/runner/environment/dependency carry-forward validity. Publishing/push/funds/adoption scope retain reserved authority.

After that obligation is complete across native attempts and specific corrections, the existing build accepts `build TAG --live --coverage FILE`. The certificate enumerates the full current inventory, immutable receipt and source hashes, exact source differences and explicit runner/environment/dependency/cleanup compatibility decisions. A decision note in the owning record binds its exact digest. This is the supervisor's reconciliation of completed evidence, not automatic validity inferred from a filename or a green component. Unresolved work, changed evidence, an unmatched candidate or a known-red component without a passing specific correction refuses sealing. The bundle records `supervisor-reconciled-full-coverage` separately from whole-command execution; original red receipts stay red. Actual live acceptance still runs through the same build entry before sealing and activation. This changes the representation of the existing full coverage obligation, not its coverage or release boundary.

After a real live failure, `build TAG --live --coverage FILE --live-coverage LIVE_FILE` continues the SAME live obligation. The exact owning-record digest binds original immutable summary/source/runtime/diffs and explicit per-case runner/environment/dependency/cleanup compatibility. Only original PASS cases may be retained. Snapshot, native fixture, distribution switch, cleanup and focus always execute on the fresh scope; every failed, pending or skipped case and every actually affected case executes again. The summary and sealed acceptance metadata distinguish retained evidence from fresh execution. Unknown/stale hashes, source, runtime, inventories or disposition refuse. No synthetic whole-run PASS, lost failure or repeated green full live run.

## Ownership and lifecycle

Before activating run ownership, inventory in-flight work. Old Brain operations
can drain on their saved release. To continue them through the new entry points,
explicitly run `record claim R-n --controller brain --adopt-brain-receipt FILE`,
using the existing `.org/settle/R-n.json`, `.org/dispatch/REQUEST.json`, or
`.org/supervisor/PROJECT-HASH/R-n.json` receipt. The claim verifies the canonical
record/project/run and binds the receipt's available release, not the new pin.
Repeat the original settle/dispatch retry or supervisor handle after claiming;
uncertain review/launch outcomes still require the existing inspection/recovery.
Do this before allowing a queued old Brain job to resume under the new runtime;
its original unbound queue member is accepted only with matching adoption
provenance. Do not use a Brain receipt to adopt ambiguous BCH work: inventory and
drain that work with its legacy controller instead.

An external Brain launcher should run `record claim R-n --controller brain`
after `record start`, before `dispatch/record-worker.mjs` and `arm-watch.sh`.
For pre-upgrade workers already recorded without a claim, explicitly use
`record claim R-n --controller brain --admit-worker` only after confirming this
is Brain's worker. This admits its own worker callback but refuses operation
receipts or other pending effects. Then re-run `supervisor entry` or arm watch.
See [run ownership](../docs/contracts/RUN-OWNERSHIP.md) for the full contract.

Only the canonical supervisor starts housekeeping. Resume existing schedules/watchers without duplicates. STOP prevents cycle mutations. A native sandbox/permission refusal stops that affected action; preserve it, never retry/relay/alternate-execute, and batch unresolved security requests narrowly. Never fabricate native/caller/claim IDs or borrow another identity. Preserve replacement-release, drained-ownership and exact-human-scope prerequisites before adoption inspect/mutation.

## Identity desks

Agents never edit another identity's files. Send its desk a short request with
what is needed, why, how to tell it is done, and where the evidence lives:
`node supervisor/request.mjs IDENTITY "REQUEST"`. The helper reuses `desk-IDENTITY`
or creates an unfocused workspace at `~/development/IDENTITY`, starts native
Codex there (which loads that identity's configuration from `.identity-root`),
waits for readiness and prompts the desk. The desk records the request in its own
record, works through its own lanes and reviews, then replies to the requester.
Never forward anything your own harness refused, including sandbox, permission
or harness settings refusals. Take those to the operator.

Before clearing the chat, record anything needed next. Durable decisions replace
conversation history; don't copy transcripts into the record. Leave watched runs
in flight and answer the operator with the result or the judgment needed.
