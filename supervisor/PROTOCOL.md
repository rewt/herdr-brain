# Project supervisor — one-page protocol

The operator sets priorities; routine reversible engineering remains delegated.
Sessions build and judge; model-free services run routine flow. The 2026-10-26
land-first design is adopted. Phase 0 changes config/data/instructions. Phase 1/2
implementations require their own start; do not describe planned service behavior
as already live.

## Run the current line

Use existing record/routes/native dispatch and one watcher per run. Consume
producer verification once; name verifier/evidence in the normal receipt. Fresh
native identity, claim generation, source/head, clean Git, main CAS/FF, STOP/HOLD
and ownership guards remain at mutations. Native refusal stops that effect;
preserve it, never retry unchanged, relay to another executor or borrow identity.
Uncertain starts/reviews and saved consumers keep their original runtime.

Queue order: finish open work; stable Brain release; BCH on it; rehearsal
publication; Chipnet withdrawal. Rehearsal/withdrawal engineering continues under
its own owner. Prioritize explicitly and hold irrelevant backlog without false
completion or discarding active claims.

Workers self-land OWN source with lane promote TOPIC --expected-head FULL_SHA,
then report. Main admits no test/review readiness gate under the current waiver.
The same owner rebases moved main and captures its new head. ONE async post-code
immutable diff/evidence review per change/item, cap1, zero suites; about30 minutes
is advisory. Retain prior pending/ambiguous/UNKNOWN attempts. One formal correction,
no re-review chain. Majors require specific correction checks before release.
Until Phase 2 implements new-commit reverts plus owner fix items, fix forward.

New cold source calls use pinned Node20.19.4 and matching HERDR_BRAIN_ROOT.
Normal pin forwarding, saved retries and native ownership remain intact.
Use supported policy writers. Instructions do not activate a runtime. Never amend
immutable reports, replay green checks or start duplicate schedules.

## Communication and decisions

Replies/milestones go to brain-chat, never the operator/quiet pane. Unsafe, native,
ownership, reserved and failed exceptions go to the PROJECT SUPERVISOR.
Operator envelopes use plain headline, what happened, action and one Details line.
Only a genuine explicitly reserved pending human question pushes once.
Apply [decision routing](DECISION-ROUTING.md); one durable note for a material
choice, not every command. Other identities execute their own actions.

## Close and release

Guarded retirement keeps working/protected/unlanded or unknown occupants.
Archive unmerged/uncommitted content before authorized removal. Source completion,
review obligations and physical cleanup are separate. Preserve callbacks/HOLD and
native receipts; no forced lock or tab cleanup.

ONE FULL final release test is shared by all fixes. Preserve valid completed
coverage; after corrections run only failing, affected or unrun checks, binding
source/runner/environment/dependency validity. Real live acceptance, corrected
Majors, sealing and installed-consumer readback precede stable activation.
Only the canonical supervisor releases. Outward rehearsal stays PRIVATE with
fresh-clone pre/post checks; publishing, funds, secrets and adoption retain their
action-bound authority checks. No synthetic PASS or early adoption scope.
